额外回查：长描述是一个线索，不是完整解释

只读解码已有 raw logits 和本地 tokenizer，没有重跑模型。实际 Transformers 后处理对每框取 token 最大 sigmoid 分数作阈值选择，再用 text threshold 解码词；它没有检验描述中的全部属性同时成立。冻结策略是 0.25/0.25、all_above_threshold，再将每框 SAM 二值 mask 做 union。

001/v1 的错误台钳框最高词元是 chuck（0.2598），001/v4 还有 pistol grip 对应的额外框；但 001/v4 错台钳最高词元属于 cordless drill，075/v4 错紫卷轴匹配 tape dispenser，013/v4 整桌框也匹配 vernier caliper。部件词召回污染与主名词识别错误都存在。Qwen 提取的 target phrase 保留了这些描述内容，当前没有证据把这些病例解释成提取器丢失属性。

这与 Grounding DINO 作者报告的细粒度 referring 局限相容，但具体病例的判断来自 R1 图像和保存中间量，而非由论文推定。Grounding DINO 原文 §4.3；官方过滤实现。实际部署 HF 文件的 SHA 和对应行号另存于私有证据包；公开仓库 HEAD 不冒充部署版本。

原始来源与本轮有关的机制适用边界
Grounding DINO / SAM 2前者文本定位，后者提示驱动的 mask；SAM 存在部件/整体歧义和细节限制当前是 SAM2.1 静态 box prompt；不能将论文视频跟踪指标当成本轮结果。
ObjectClear §3.2mask 内外观形成目标视觉条件；ATA/AGF 处理对象影响区域及融合错误 union 可能污染目标条件，这是基于架构的推断；未保存相应 attention 来证明病例因果。R1 的 20 steps/guidance 1.0 对应论文 benchmark 设置。
OSOR §3.4、Table 5、App. B.5当前使用 FLUX Phase II，学习效果区域 alpha，对欠覆盖/扰动 mask 有训练设计欠覆盖鲁棒性不保证从完全错对象或空 mask 恢复；latent 融合后还有 VAE decode，alpha 也不等于最终像素改动图。
Segmentation foundation model limits即使有标注辅助的 tight box、正负点与 oracle 候选选择，细结构和可分性仍可能构成限制提示优化值得诊断，不承诺解决全部细结构，也未证明本集有同样统计规律。
Matcher参考图与参考 mask、双向特征匹配、SAM proposals可借鉴对应验证，但参考 mask 是额外条件；语义近似不是同一物理实例。

可以怎么解决：先定位信息缺口，再决定是否需要图组

第一优先：验证目标身份，再组装可见部件。 保留候选，而不是默认把所有候选当成一个目标；显式核对主名词、属性、完整物体与部件关系，对整桌框和互不相干实例给出可追溯的拒绝/不确定记录。可比较 head-noun 检索与完整描述验证，但不能把本轮已挑出的病例当成调参后独立 test。对电话类再检查自动部件提示、多个候选 mask 与邻物排除；不能把 SAM predicted IoU 当身份分数。这些都是待验证方案，未实施。

第二优先：在共同 mask 下检查后端的修改范围。 对同 query/raw/seed/backend，分别保留正常预测 mask 与单独标明的 oracle-visible 诊断条件，才能较好分离上游定位与生成瓶颈。oracle-visible 仍不等于理想对象影响区域。对 080/v1 与 083/v4 这样的反向病例检查已保存 alpha/改动图，而不是先宣布换一个后端就能解决。ObjectClear 和 OSOR 已有影响区域机制，研究贡献不能仅重复“再加一个 alpha”。本轮未启动这些诊断运行。

第三优先：让图组补充确实缺失的目标证据。 仅当 query 的身份/部件歧义在较强单图条件下仍存在，且 raw support 确实展示同一物理实例的关键属性时，才有证据支持图组路线。一个可研究的流程是：自动提出 query 候选 → 用多个 raw views 验证同实例与可见属性 → 只产生 query 中可见目标 mask → 交给固定删除后端。跨视角不能直接拷贝 amodal mask 或吞掉前景遮挡物，也不能把支持图背景当作已知真实隐藏背景。

后续若获授权，可用相同后端/像素/seed，先冻结相同的阈值后框池，分别控制单图验证、自动 support、去掉关键 support、无关 support，检验池内身份验证，区分“多了一张图”和“多了目标特异的信息”。这一控制不能回答跨视角是否改善候选召回；零候选仍须留在失败分母。若另研究召回，则需单列并冻结 raw proposal 预算与过滤规则，报告候选池变化，不能混同为验证能力提升。支持图的选择与顺序须冻结并留失败分母；由 GT 挑 support 或提供 reference mask 的条件只能单列 oracle。人工先判定这些候选病例的对象身份、部件归属和 GT 是否合理，再决定最小诊断范围与资源预算。
